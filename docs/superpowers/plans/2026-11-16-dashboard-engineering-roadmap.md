# Space Call — الخطة الهندسية للمرحلة التالية

> طلب المستخدم وضع خطة هندسية والبدء بالتنفيذ. النطاق: لوحة التحكم، مع إعطاء الأولوية للتحليلات التي أُطلقت حديثًا. نبدأ بمرحلة مستقلة قابلة للاختبار والمراجعة، ثم ننفذ بقية المراحل على دفعات.

## ما كشفته المراجعة

1. حدث فرق فعلي بين اكتمال دمج الواجهة وجاهزية دوال التحليلات في قاعدة البيانات. Cloudflare ينشر `main` تلقائيًا؛ اختبارات البناء المعزولة لا تثبت أن قاعدة الإنتاج استقبلت الترحيل.
2. إعدادات الفترة والمقارنة والعملة وفلاتر التنبيهات محفوظة في حالة React فقط. تحديث الصفحة أو الرجوع من منتج قد يفقد سياق التقرير.
3. بطاقات المبيعات تفتح صفحات المبيعات والطلبات دون نقل الفترة والعملة، مما قد يعرض تفاصيل تختلف عن إجمالي البطاقة.
4. حد المخزون ثابت: منخفض حتى 10 وحرج حتى 3؛ لا توجد سياسة حد مستقل لكل متغير حتى الآن.
5. رسم 12M يعرض نقاطًا يومية، وقوائم الأداء محدودة بثمانية منتجات. يلزم قياس الاستعلامات قبل إضافة التجميع الشهري والتصفح الكامل.
6. لا يوجد مبلغ استرداد جزئي مسجل في دفتر المبيعات؛ لذلك لا يجوز تقديم صافي بعد الاستردادات أو أرباح دقيقة باعتبارها حقائق متاحة.

## القرار المعماري

التوسيع داخل البنية الحالية: React + TypeScript + Recharts + Supabase مع فصل `pages/components/data/lib`. لا إعادة كتابة للوحة أو المصادقة. صلاحيات قاعدة البيانات، MFA، RLS، وعمليات المخزون الذرية تبقى المرجع.

البديل الأول كان إضافة مزايا واجهة جديدة مباشرةً؛ يضيف قيمة ظاهرة لكنه يترك فجوة الإصدار التي ظهرت فعلًا. البديل المختار لهذه الدفعة هو تثبيت مسار الإصدار أولًا، ثم تحسين سياق التقارير. هذا ترتيب هندسي اقترحه المنفذ بناءً على الحادثة، وليس قرارًا ماليًا جديدًا مفروضًا على صاحب المتجر.

## الدفعة الحالية: خطة تنفيذ P0

**الهدف:** منع تكرار نشر واجهة Analytics قبل وصول تبعياتها، دون فتح بيانات التحليلات للزوار.

**ملفات التنفيذ:**

- `scripts/lib/analytics-release.mjs`: إعداد اتصال عام فقط، طلبان RPC محدودان، مهلة زمنية، وتصنيف fail-closed للنتائج.
- `scripts/check-analytics-release.mjs`: مدخل CLI برسالة حالة مختصرة لا تطبع مفاتيح أو استجابات أعمال.
- `src/dashboard/lib/analyticsErrors.ts`: تحويل خطأ الدالة المفقودة إلى رسالة خدمة مفهومة.
- `src/dashboard/data/analytics.ts` و`src/dashboard/uiTranslations.ts`: وصل التحويل والترجمة مع بقاء الأخطاء الأخرى مستقلة.
- `package.json`: أمر فحص وأمر نشر محمي، مع إبقاء البناء المحلي والمعزول قابلين للعمل دون شبكة.
- `e2e/dashboard-analytics-release.test.mjs`: اختبارات استجابات API، المهلات، رفض المفاتيح المميزة، وعدم طباعة بيانات حساسة.
- `e2e/dashboard-analytics-browser.mjs`: سيناريو عدم الجاهزية ثم التعافي وزر إعادة المحاولة.
- `docs/dashboard-analytics.md`: تعليمات النشر الآمن والقيود ومخرجات التحقق.

**العقد:** الفحص لا يستخدم جلسة موظف ولا service-role. يرسل فقط مفتاحًا عامًا إلى دالتين للقراءة. النجاح هو رفض التنفيذ بصلاحية PostgreSQL `42501` للدالة المطلوبة نفسها؛ الدالة موجودة ولكن الزائر ممنوع. الدالة المفقودة أو فشل الشبكة أو المفتاح غير الصحيح أو استجابة أعمال ناجحة أو استجابة مبهمة تمنع النشر. هذا يثبت وجود التوقيع ومنع وصول الزوار، ولا يحل محل اختبارات النتائج تحت صلاحيات الموظفين.

**المراجعة المطلوبة:**

- عدم اعتبار أي 401/403 نجاحًا بلا التحقق من رمز الخطأ والدالة.
- رفض مفاتيح سرية وJWT بأدوار مميزة قبل أي اتصال.
- عدم اتباع تحويلات HTTP تحمل المفتاح إلى مضيف آخر.
- عدم قراءة أو طباعة جسم استجابة 200 التي قد تحتوي بيانات أعمال.
- ألا يخلط تعذر اكتمال الترحيل مع فترة مبيعات فارغة أو يعطل بيانات المخزون المستقلة.

**خطوات التنفيذ:**

- [x] كتابة اختبارات سلوكية وتشغيلها لإثبات الفشل الحالي.
- [x] تنفيذ الفحص وتصنيف النتائج وربطه بأمر نشر محمي.
- [x] إضافة رسالة عدم الجاهزية والتعافي واختبار المتصفح.
- [x] تشغيل الفحص العام للقراءة على المشروع الحالي وتوثيق حدود إثباته.
- [x] تشغيل typecheck وlint وtest:unit والبناء وSSR واختبارات المتصفح المناسبة.
- [x] رفع فرع مستقل وطلب دمج يتضمن الخطة والنتائج.
- [ ] بعد الدمج: توصيل أمر النشر الجديد بمشغل Cloudflare بعد وصول السكربت إلى `main` حتى لا يشير الإنتاج إلى ملف غير منشور.

لا تغييرات مخطط أو بيانات أعمال في هذه الدفعة. لا نضيف تكاليف أو مراقبة خارجية أو رسائل لفريق آخر. بقية المراحل مستقبلية، ولكل منها تعريف قبول واختبارات ودفعة منفصلة.

## نتيجة تنفيذ الدفعة الأولى

- مجموعة الاختبارات الكاملة: 821 ناجحًا، دون فشل أو تخطٍ، منها 13 اختبارًا جديدًا لبوابة الإصدار.
- نجح فحص الأنواع والبناء وSSR وفحص المستودع الأمني؛ lint دون أخطاء مع 27 تحذيرًا موجودًا مسبقًا، ودون ملاحظات على ملفات التنفيذ الجديدة.
- نجح اختبار متصفح مبني على حزمة الإنتاج، بما فيه الدالة المفقودة وإعادة المحاولة واستقلال المخزون، والهاتف وRTL والوضع الداكن.
- نجح فحص الجاهزية للقراءة على قاعدة المشروع الحالية بمفتاح عام فقط، دون جلسات موظفين أو قراءة بيانات أعمال.
- أمر النشر المحمي جاهز في الفرع. توصيل مشغل Cloudflare به خطوة نشر لاحقة لدمج هذا الفرع؛ لا نعتبر المسار التلقائي محميًا قبل تنفيذها.
